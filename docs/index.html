Homebrew가 더 이상 지원하지 않는 오래된 Mac을 위한 패키지 관리자
A package manager for old Macs that Homebrew dropped support for — Monterey and earlier, still covered.

$ /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/hoyacom/jige/main/install.sh)"

새 Mac이어도 상관없습니다 — Homebrew도 MacPorts도 설치돼 있을 필요 없습니다.

Homebrew가 더 이상 지원하지 않는 Mac을 위해

brew doctor를 돌리면 "Your Mac OS is too old" 같은 경고가 뜨고, brew install이 구버전 macOS(Monterey, Big Sur, Catalina…)에서 더 이상 bottle을 안 받아줄 때가 있습니다. Apple Silicon이 아닌 오래된 Intel Mac, 2015년식 iMac처럼 더 이상 공식 지원 목록에 없는 기기도 마찬가지입니다. jige는 이런 기기에서도 — Homebrew를 설치하지 않고도 — Homebrew·MacPorts가 공개해둔 레시피를 그대로 읽어서 이 기기에 맞는 버전을 찾아 설치합니다.

If brew refuses to run on your old macOS (Monterey, Big Sur, or earlier) or your unsupported Intel Mac, jige reads Homebrew's and MacPorts' own public recipe data over plain HTTP — no Homebrew installation required — and installs the right build for your exact OS and architecture.

짐(jim)과 도구(dogu)

Homebrew가 설치 대상을 formula(터미널용)와 cask(Dock에 뜨는 GUI 앱)로 나누듯, jige는 OS에 상관없이 똑같은 질문 하나로 나눕니다.

한 번에 검색, 한 번에 설치

Homebrew(Cask/Formula) + MacPorts + 자체 레포지토리를 동시에 뒤져서 어디 소속인지 분류까지 보여줍니다. 전부 공개 HTTP API라서, 이 기기에 brew나 port가 전혀 없어도 검색·설치가 됩니다.

명령어

brew와 port 둘 다 쓰는 이름 그대로 맞췄습니다.

jigebrewport
jige search <검색어>brew searchport search
jige install <이름>brew installport install
jige info <이름>brew infoport info
jige upgrade [이름]brew upgradeport upgrade
jige listbrew listport installed
jige uninstall <이름>brew uninstallport uninstall

왜 만들었나

Mac이 여러 대(Apple Silicon, Intel+Homebrew, Intel+MacPorts)인데, 전부 Homebrew로 통일하고 싶지는 않았습니다. 그런데 Homebrew-Cask는 "어떤 OS/아키텍처에 어떤 파일을, 어떤 체크섬으로" 받아야 하는지를 이미 공개 JSON API로 정리해두고 커뮤니티가 계속 최신으로 갱신해줍니다. jige는 이 JSON만 HTTP로 읽어서 brew 바이너리 없이 같은 정보를 활용합니다 — 이미 있는 레포(Homebrew-Cask, MacPorts)는 그대로 래핑하고, 둘 다에 없는 것만 자체 레포지토리에 직접 추가합니다.
